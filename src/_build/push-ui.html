第 3 步 · 说清楚这一轮改了什么「重新量一遍」量出这一轮的现场（哪几家会动、号会变成什么）；下面每一格的字都归你填，空着那一笔就不落。填完点「落笔到各支」，改动才真的进了仓 —— 不落笔，第 4 步那些勾永远还是"还没拆"。
第 4 步 · 挑这一枚包里带什么只影响打出来这一枚的内容，不决定推哪几条分支：插件那七家一家一格，功能那八项一项一格。装好的软件里不出现这一栏的任何字。
第 5 步 · 本地打包，你手动测从工作树站的这一棵出，跑三趟（生成页面 → 铺出厂镜像 → 出发布物），不提交、不打 tag、不推。Flow-Desk 得先退干净。
第 6 步 · 本地全功能那一枚（可选）把勾中的那几条本地前瞻支合到集成分支上，再从那一棵打一枚 —— 这一根永不进远程。
第 7 步 · 推送并建 PR基础那一支（这一轮那条支）走左边这颗：同步 → 开支 → 落笔 → 扫公开面 → 要你亲手敲一个「推」字 → 推 → 建 PR。功能那八项推不推，是右边那八格的事：勾中哪几格，才推哪几条前瞻支、各建一个 PR；没勾的一条都不推，留在本地。
第 8 步 · 你在 GitHub 网页上人工合并这台不合并：你核对 diff、亲手点 Squash and merge，并勾上合并后删掉远程那条支。这一颗只是问一眼「合进去没有」。
第 9 步 · 本地收尾再同步一次 main，然后把这一轮发完的那条支从本地删掉（没合进 main 的那一颗都不删）。
第 10 步 · 打包发版（号钉在 main 那一笔）这一颗要三样都齐：盘上干净、站在 main 或拼装那一棵、这一轮那条支已经合进 main。七家的号、tag、发布物一起落。
